# 普通用户 Dashboard 的最小实施方案

## 实施边界与结构

正式源码继续位于 `example-cv-users/`；未来文档/证据放 `resume-users/S4/S4.n/`。旧 CMS 仅是只读参考。保留 Users 的 Vinext/现有路由与 S2 服务端 Cookie 会话，不引入 React Router 来包住旧 CMS，也不复制 Supabase 浏览器客户端。

建议受保护的 `/dashboard` → Overview、个人资料、简历内容、联系/站点文字、预览；文件、活动记录、历史、发布和 AI 入口按能力开放。账户与改密沿用 `/account`、`/change-password`；注册、登录、验证及恢复页面保留。UI 语言与简历内容语言分别切换。

S4.1 必须同步扩展现有 Worker 的**受保护页面范围**来验证 `/dashboard` 会话，并保留原 S2 行为。当前 Worker 只显式保护 `/account`、`/change-password`；仅加一个客户端 Dashboard 页面不构成保护。不得顺带打开 `/api/*`：当前非账户 API 的 404 是既有闭态边界。

UI → Users ViewModel/适配层 → 独立审核的 Users 服务端接口 → S3 可信身份/资格/本站资源校验。浏览器只提交定位及表单输入，服务端逐次验证 UID/Session、Grant/epoch/generation/hold、Owner 和资源；UI 隐藏按钮不构成授权。未开放的能力由服务端确认，不能将“没有配置”当作空站点。

## 核心状态与动作

| 状态 | 展示及允许动作 |
| --- | --- |
| 验证中/加载中 | 骨架和可访问 busy；不显示 fixture 内容，不允许编辑提交 |
| 未登录/会话失效 | 沿用 S2 的登录引导；清理本站内存草稿，失效请求不得回写 |
| 身份服务暂不可用 | 可重试错误，不能伪装未登录、未建站或空数据 |
| 业务未配置/无资格 | 清楚提示相关能力尚未开放；账户功能可用；不创建 Grant 或连接旧 CMS |
| 已确认无站点 | 只在可信“mine”返回 site=null 时成立；实际建站另受接口、权限和用户动作约束 |
| 有站点、只读 | 显示服务器规范化数据及能力；不把 S3.3 的 edit=false/publish=false 改成 true |
| 本地 dirty | 预览即时更新；离开提醒；取消回已确认基线；禁用的真实保存不得伪造持久成功 |
| 保存中/成功 | 同域写锁；成功须持久回执+规范化聚合+新 revision，再更新基线和提示 |
| 409 冲突 | 保留本地表单，提示读取新基线并人工处理；不自动覆盖或发布 |
| COMMIT_UNKNOWN/传输不明 | 保留原 request_id/摘要并阻止新操作；只读对账。未观察到记录不证明失败，不生成新键重试 |
| 403/撤销 | 停止业务动作，清理授权范围缓存；不回退直连或旧 API |

## S4.1–S4.12 建议映射

已核查源码与 S3 文档，未找到既有的十二步正式逐项定义。以下是**建议的最小拆分**，用于对齐范围；不是已经完成的功能，也不代表本轮批准实施。每步只纳入本步源码、必要测试与 `S4.n/` 证据，独立 Commit/Push，按实际规则检查，不自动 Merge。

| 步骤 | 最小开发范围 | 最小验收与依赖 | 暂缓/不混入 |
| --- | --- | --- | --- |
| S4.1 | Dashboard 受保护外壳、Overview、分组导航、双语 UI、账户入口；业务未开放态 | S2 保护链正确覆盖新页；未登录、有效会话、临时失败、移动导航/键盘；S2 回归 | 不接新 DB/Grant，不调用旧 CMS，不做建站/保存/发布 |
| S4.2 | 本站状态与读取适配，ViewModel、能力/加载/空态/错误 | 合成合同可先做；实际 mine/建站链须独立批准运行；无站点与不可用严格分离 | 不默认建站；不假设泛用 S3 内容读取接口已存在 |
| S4.3 | Profile + Introduction 最小文本编辑，shared/zh/en、取消/dirty/本地预览 | 稳定 ID、两语不丢失；缺真实接口时只接受局部 UI 验收，保存关闭 | 不做头像，不把 mock 保存计为持久成功 |
| S4.4 | Education + Experience 文本表单和分类 | 复用配对输入/重复项，验证空值、长文本、分类与双语；依赖 S4.2/3 模型 | 不扩展 AI/文件；后台字段/接口不齐则保留阻断 |
| S4.5 | Projects + Skills + Awards 文本表单、Projects 各语言 methods | 父子稳定 ID、嵌套数据、无意覆盖负例；复用共同编辑骨架 | 不新增项目图片、复杂拖拽、批量发布 |
| S4.6 | Contact、Site & Links、栏目标题/导航文字 | URL 协议白名单，字段唯一归属；账户邮箱不自动成为公开邮箱 | 不做 DNS、自定义域名注册、站点公开切换 |
| S4.7 | 文本聚合真实保存适配；全模块双语/排序一致性、CAS/幂等/UNKNOWN | 先 Introduction 纵向打通再扩模块；须 G-SAVE；真实普通身份、双语原子性、冲突/重排/未知对账 | 没有服务端合同或真实验收就停在 UI 层；不得依靠旧 DML 补接口 |
| S4.8 | 完整文本预览：本地未保存与受保护已保存来源分开；宽/窄屏切换 | 纯 mapper、两语、链接、dirty 标记、来源/时间/revision；已保存私有预览须 G-READ/G-SAVE | 不把本地预览变匿名公共路由，不用预览绕过资产授权 |
| S4.9 | 头像/文件占位与授权状态；通过门槛后仅私有 PNG 最小链 | G-STORAGE；精确对象/持久哈希/不可覆盖/跨站拒绝/撤销与引用保护 | PDF、永久 URL、历史签名、删除/清理仍关；PNG 内容校验不等于 Storage 可用 |
| S4.10 | 本站 Activity Log 和 Version History 安全只读投影、过滤/分页/差异 | G-HISTORY；无日志/无权限/未开放分开；恢复另需 G-SAVE 及独立恢复事务验收 | 不复制旧 actorEmail 管理员搜索，不做平台审计；恢复可继续禁用 |
| S4.11 | 发布确认、状态/公开地址、撤回 UI；通过门槛后接文本快照 | G-PUBLISH；草稿≠公开、CAS、匿名投影、撤回/Outbox/缓存版本实证 | 不操作 Cloudflare、DNS 或部署；不把本地事务模型当已发布 |
| S4.12 | AI 建议入口及明确不可用态；有独立服务后才做选字段/预览/采纳；全流程收尾报告 | G-AI；最小授权输入、超时/错误、采纳只进 dirty 表单；完成 S2/租户隔离/无泄漏/可访问性回归 | 不默认选 Provider，不发送真实简历、不赋写库/发布权限；缺门槛则部分交付并列阻断，不能宣称 S4 全验收 |

## S4.1 具体推荐

只增加 Dashboard 页面和局部组件/样式、服务端路由会话保护所需最小调整及合成测试。显示“内容功能尚未开放”及真实账户入口；不虚构建站/保存/发布状态。测试应证明新页不可匿名访问、身份临时失败不误重定向、S2 账户与恢复行为未回归；浏览器检查桌面、窄屏、双语、Tab/Escape/焦点。业务按钮保持明确不可用，不展示可以操作但必然请求闭态 API 的控件。

最低交付为应用变更+必要验证+S4.1 报告。若用户希望首屏即读取真实站点，则先批准对应 S3 运行/接口条件，范围需单独对齐；本 S4.0 不执行它。
