# G5 v1：身份、站点与权限合同

状态：已审核方向的规范性设计（INFERRED / REVIEWED DESIGN），实现和测试均NOT TESTED。
本合同不授予任何部署、SQL或真实账号测试权限。技术未决项见[Session合同](AUTHORIZATION-AND-SESSION-CONTRACT.md)。

## 可信身份

1. 身份域固定Users项目；服务端验证issuer/audience/有效期、sub/session_id、getUser UID一致及已验证邮箱。
2. auth_user_id来自上述服务端结果；body/URL/Header里的user_id、actor、email只可作输入，不可授予身份。
3. 自解码JWT、getSession对象、UI返回用户对象、user_metadata均不能独立授权。
4. 请求级上下文不得跨请求共用；现有Auth transport只允许Auth路径，新业务采用独立适配层和用户JWT。
5. 不用service_role加客户端UID替代普通用户链路；高权限访问不是RLS证明。

## 首版单站与Owner

- sites.owner_auth_user_id是唯一权威Owner；非空FK到本项目Auth UID，首版全局唯一。
- 每账号最多一个owner站点；注册不自动公开，不开放第二站点、团队邀请或转让。
- site_members主键(site_id,auth_user_id)，恰好一条active owner镜像，UID等于sites权威值。
- owner镜像不能单独授予Owner；两侧不一致时拒绝业务访问，不自动修补。
- 普通内容接口不能写owner/member/role/state；建站在同一数据库事务维护镜像。
- 软删除首版保留建站名额；恢复/清理/重新建站规则仍需确认，不通过重建site_id绕过限制。
- 未来多站点可移除单站限制，已有site_id与成员关系保持稳定。

## Session能力

| 状态 | 业务权限 |
|---|---|
| 已验证普通登录且有效business grant | 按本站权限 |
| 注册或邮箱验证但未取得业务资格 | 引导普通登录，不自动授予 |
| Recovery Session/grant | 仅既有恢复流程；不能建站、读草稿、文件或发布 |
| 过期/撤销/epoch不符/身份UNKNOWN | 拒绝私有业务 |
| 同浏览器并存普通与恢复会话 | 互不借用；分别判断 |

Cookie的account/recovery命名分离不证明直接Recovery JWT无法访问REST/Storage。
资格必须在Worker、数据库/RPC、Storage一致执行；不能只靠UI或某次登录后的缓存。
未来S2集成点仅在另批后实现，不能把当前Cookie任意升级为business grant。

## 资源与内容归属

- site_id为永久UUID，record_id为稳定记录ID，domain/slug为可变路由标识，三者不等价。
- 客户端site_id仅用于定位，每次校验UID→成员/Owner→站点状态→资源。
- 所有租户内容、翻译、嵌套方法、文件、历史、审计有明确site归属。
- 子记录通过(site_id,parent_id)复合FK关联父记录；不能分别引用合法site和别人的合法parent。
- 普通更新不得修改site_id或父级；排序/语言切换不改变ID。
- 单语言编辑不静默删除另一语言；共享字段、翻译、排序及嵌套关系按聚合事务保存。
- source_key仅是来源标识，不能作权限凭证。
- hostname规范化且全局唯一；保留admin/cms-admin/www/api/auth/hr/mail等；未知Host不回退到默认租户。

## 草稿、文件与公开

保存/注册/上传均不公开。只读当前启用域名解析的合法已发布快照；公开字段白名单。
私有预览、历史、资产需要本站授权，不允许共享缓存或猜路径获取。
取消发布保留publication状态行、清空当前snapshot指针并递增公开状态版本；旧缓存不得绕过门禁。
历史恢复产生新草稿版本，不自动公开；曾经公开不代表历史永久匿名可读。
私有文件路径不是授权，签名URL有期限和泄漏边界，已下载副本无法收回。

## 新旧系统与未来角色

旧CMS的owner/qa、固定example-cv目标解析、HMAC/vault配置和生产数据不能复制到Users。
相同email不建立跨项目身份映射；旧CMS token不能在Users身份域被接受。
首版只启用Owner；未知/未来角色默认无私有权限。平台运营不默认拥有全站访问。
AI只处理用户明确选中的授权字段，不能直接写库或发布；模型无数据库权限。
HR身份/企业成员不属于候选人的site_members；公开建站与人才库同意是独立授权。
S3不创建人才搜索索引，不开放HR/AI业务。未来投影需字段许可、撤回、缓存/索引清理合同。
