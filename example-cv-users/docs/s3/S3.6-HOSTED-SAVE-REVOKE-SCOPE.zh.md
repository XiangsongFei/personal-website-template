# S3.6 托管保存回滚与撤销范围

唯一目标为 `vellypyadcxkvqftsbrg`，沿用已安装的 9 项迁移及 02、测试账号和站点。启动前以独立 TLS 会话核对 PG 17.12、闭态目录、历史回执和 Alice/Bob 草稿与发布版本 5/0、2/0。发布 ACL、公开读入口和 Outbox 保持关闭。保留待投递事件。

- 使用既有账号各进行一次密码登录。仅一个新签署代次，最长 30 分钟。两次 R3 登记和 Grant 签发，以及一次针对 Bob 本次 Grant 的 R3 登记和撤销。阶段前记录 Proof ID，验证真实 Session、站点 Owner、当前 epoch 和代次。
- 仅创建 `site_private.s36_test_abort_save()` 和 `site_private.text_publication_audit` 上同名延迟约束触发器。函数归既有 `ecv_s3_integrity` 所有，显式撤销默认和平台调用角色权限。部署角色的事务内权限在提交前归还。触发器函数比较 Alice 的站点、UID、Session、保存动作、版本、首次使用的请求键以及规范化命令摘要，再证明同事务的草稿及版本和成功回执已写入。使用正常提交模式发送一次保存。PostgREST 的专用 SQLSTATE 由本地 mTLS 入口记录，入口的常规拒绝响应保持一致。独立查询证明回滚，移除两个归属一致的对象后才开展撤销业务探测。
- Alice Session 和 Bob Grant 的测试各使用一次本人正向读取及一次本人撤销后读取。Alice 通过 Supabase Auth 的 `scope=local` 注销，核对该 Session 已移除、其他 Session 和该 Grant 未变化，并使用尚未到期的原凭据验证业务拒绝。Bob 通过受信 R3 路径撤销其本批的精确 Grant，核对登记、消费回执和 `user_logout` 原因并验证 Auth 仍接受原 Session、实际业务入口明确拒绝。
- 远端写入异常即停止后续用例。仅独立对账原对象和原请求键。定位明确的测试对象按审查过的移除脚本收尾，随后复核目录和权限。不可确认的写入保持 UNKNOWN。关闭本地 PostgREST 和 mTLS 服务，保留原始私有回执，Git 只记录脚本和脱敏结果。

`scripts/s36-hosted/save-revoke-acceptance.mjs --readonly-baseline|--execute-approved <私有运行目录绝对路径> <已验 TLS 的 psql 包装器绝对路径>` 使用运行目录下的 `stage`、`journal`、`private`。先复制获批 SQL，将 `save-fault-*.sql`、`save-revoke-observe.sql`、原 `publication-generation.sql` 和 `publication-target.sql` 冻结到 `stage`。运行期间生成的授权限定 SQL 和观察记录使用独占文件。专用本地入口的可选第三参数为本次 `private/fault-plan.json`，缺少该参数时采用现有普通验收入口。凭据沿用既有 0600 测试配置。
