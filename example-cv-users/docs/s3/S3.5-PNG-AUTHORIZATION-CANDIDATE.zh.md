# S3.5 私有 PNG 授权候选

这份切片覆盖 `prepare`、`claim` 与 `authorize-verify` 三种 PNG 元数据动作。既有 M5/M7 和 Registrar 继续负责 Grant 签发、过期、精确撤销与安全 epoch。使用既有身份适配器绑定账号句柄。在业务动作事务内使用数据库时钟和当前来源行，联合核对实际 UID/SID、站点 Owner、活动成员、Grant、epoch、签署代次及操作专用 Permit。全局业务门与 proof verifier 门须显式开启才可接受资格。源端负责提供并验证实际角色和数据库锁。

| 边界 | 接口合同 |
| --- | --- |
| PNG 输入 | 使用已解码的 `preparePrivatePng` 输出的 prepare DTO。它描述 PNG 的精确字节数、SHA-256、站点和 prepare 请求键。文件路径由站点、资产及对象版本推导。Claim 时尚无原生版本，授权 Verifier 时必须绑定已落库的精确原生版本。 |
| 同一事务 | 受信 adapter 从传入的已验证账号句柄建立受约束请求，并在锁下提供实际 actor、活 Session、站点/Owner、Grant、代次和 Permit 的同事务查询结果。毫秒时间字段使用数据库时钟。锁须覆盖权限撤销和原键冲突；数据库需在同一提交内保存请求 UUID、意图摘要和结果，并以唯一键阻止跨主机重派。 |
| 恢复 | 服务器固定受保护日志根，按原请求 UUID 派生唯一目录。独立 observer 凭原键、作用域、动作和提交 XID 取证。单次空查不能成为 settled absent，需要可靠的事务终结或防晚到见证。主管从受保护清册重载原 UID/SID、请求及动作内容，过期 bearer 不入盘、无需恢复。恢复入口只走原键对账和已证可关闭的动作。 |
| 命令关闭 | 拒绝、零业务或未决原提交不派发补偿。存在原事务的独立提交证据后，adapter 再在源端核对原键和精确临时命令资格才可收尾。命令闭态只统计该动作的临时命令租约、执行和晚到提交。用于下一阶段的持久上传资格仍按生命周期合同处理。 |
| 其余业务 | create-only Storage 上传、可信 Verifier 回执、Seal、READY、发布及完整角色和会话退出由独立生命周期实现与验收。在调用未接入真实事务和独立来源之前，此切片只有本地证据。 |

候选不新增路由、Worker 配置、迁移或永久权限。PostgreSQL 17.12 夹具使用 Unix socket、独立写入/观测角色和合成身份，证明本机提交 XID、断点原键和跨进程关闭。它没有运行 Supabase Auth、Storage 或真实 RLS。历史 B07 四组功能性 HOSTED PASS 档案沿用，原生 RLS 归因和正式下载门未解除。
