# S3.3 delivery and deployment boundary

This PR ships disabled database foundations, server-only business components and reproducible offline
security tests. It does **not** deploy Workers, apply production SQL, configure credentials or expose APIs.
Existing worker/index.ts, S2 account/session/recovery implementation and wrangler.jsonc are unchanged.

Historical M1–M7 SQL must retain its reviewed bytes, order and isolated project checks. The necessary
clean-project rebinding is archived only under tests/s3/fixtures/clean-project-binding.sql: it was a
separately authorized experiment, not M8 or a production migration. Do not run it against an existing
system. A production rollout needs a newly approved physical/logical target, generic target binding,
certificate/HBA/service identities and a separately reviewed forward migration.

No runtime enablement SQL, signing keys, certificates, service passwords, active Docker configuration,
Mac paths or raw receipts are included as production configuration. Synthetic addresses and public
MAC vectors are confined to test fixtures/plans or immutable isolated SQL history. Test modules never
provide live credential sources. The default runtime and verifier remain forced off after M7.

The private service deployment entry startPrivateRpcService is disabled by default and requires
explicit server configuration, protected certificate material, a read-only UDS mount and successful
owner/group/type/inode/permission preflight. It uses an exact frozen private authority and registrar
SAN. Do not use a public authenticator's service_role path. The browser has no database connection,
registrar certificate or HMAC key. Production trust acceptance is documented in the ADR.

CI runs npm build/typecheck/test/audit; npm test includes S3 Node, workerd and Python source/ACL/model
suites. No live DB, Auth, Proof, Grant, Docker or cloud operation is part of those tests. Live historical
results and new offline regression results are separate. No CI deployment or database migration step
is introduced. PR merge alone must not activate S3.
