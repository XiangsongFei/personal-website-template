## Owner mirror 与公开 HTTP

Owner 探针只在一个回滚事务中尝试删除 Alice 绑定的唯一 active Owner mirror，强制已有约束立即检查，收到 `23514 owner/publication invariant`，并确认 mirror 恢复及独立业务读回一致。这是原生约束的阻断证据。既有私有入口以专用登录校验 Session，另一 SQL 连接的未提交夹具对其不可见，已提交的缺失状态又被约束阻止。R05 私有入口失效证据仍缺。最小后续范围须另行明确批准一个同事务测试入口，仅绑定 Alice 的真实 Session 和固定站点，先用原 RPC 正读，再在子事务内暂时移除 mirror、调用同一业务授权并核对拒绝，回滚夹具后通过原入口及独立会话复核恢复。该方案保留现有约束和角色，需要提前列明临时入口 ACL 和移除步骤，业务事件增量为 0。

本地 HTTPS 最终执行 8 个请求，均由摘要核对后的原 Worker 候选实际处理。两个合规主机请求各调用一次指定托管项目的匿名 RPC，均返回 PostgreSQL `PT404`。旧快照路径、额外 snapshot/site ID、非法和重复 locale、与可信 URL 不一致的 Host 均在本地实际处理器拒绝，未调用上游，响应包含 `no-store`。首次本地证书握手在任何业务调用前停止，保留空回执。修复证书校验使用真实 loopback IP，应用仍用原始 Host 校验。最终请求与回执记录在 `public-transport-recheck`。本批两站保持未发布，没有公开内容 200 对照。

原 R18 双站公开正向若补齐，最小发布范围为本批收尾之后由两站合法 Owner 各发布一次、验证后各撤回一次。Alice 可复用旧快照，publication_revision 预计 5→6→7；Bob 使用现有草稿，预计 0→1→2。新增 4 条事件，不碰本批五条终态。需要相应的专用可撤回测试域名激活、公开读和发布 ACL 明确范围，恢复两站未发布并独立读回。Bob 必须沿用已推进的 epoch 1。若一并批准 R24 的真实接收后丢失应答，可用新产生且当时仍当前的 Alice revision 6，另一次受限 loopback 发送；原 revision 3 UNKNOWN 不可用作重发材料。
