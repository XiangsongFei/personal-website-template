# S3.8 本地闭态执行适配候选

此切片将已合并的私有 PostgREST、独占持久账本与 PostgreSQL 源端事件匹配器接入同一本地执行入口。既有 A 14/14、B 52/52 取证保留。新增实库夹具只跑两个代表性 RPC，并验证失败恢复。S38_LOCAL_READY 保留，HOSTED_GATE_2_NO_GO，FORMAL_DOWNLOAD_BLOCKED。

- 接受 A 的 14 项或 B 的 52 项以内的冻结子集，按原作用域限制 RPC、参数和动作。仅放行文本读取、四个既有命名空间中的文件读取、history、prepare。业务请求固定 POST，限制为本机专用 Unix socket。夹具绝对目录、专用角色及数据库目标指纹须匹配。PostgREST 始终强制事务回滚。
- 按原请求 UUID 在派发前持久记账。绑定已验证账号 UID/SID、预期拒绝、确定的请求体摘要和原决定函数。仅接受来自本机 PostgreSQL jsonlog 的真实分支事件及同一 backend/事务的下一条原生 SQLSTATE。夹具按实际数据库参数重新计算摘要，独立核对 wire 错误响应与源端痕迹。夹具的函数指纹覆盖实际拒绝分支 SQL，完整数据库函数定义和托管请求原始字节须按供应商合同独立取证。Auth 使用合成身份，源端证明范围限本地夹具。
- 如果 wire 或源端回执缺失，停止其余计划项。重开同一账本只能读取原请求源端以及独立闭态。原生证据确认拒绝时，可以确认该业务效果不存在，丢失的 wire 回执仍为空。若原键无法确认、仍可能有晚到提交或闭态证据不足，保留未决。独立终态要求保护摘要一致、门关闭、进程与 socket 退场及专用连接为零。
- 本切片不连接 GoTrue 或 Storage，不创建或恢复任何托管账户、SID、角色或数据库函数。联动真实 Auth 生命周期、原生 Storage RLS 及托管源端独立观察仍按原合同、工单和授权处理。本切片不改变 S3.5 原生严格前置、正式下载或生产配置。

真实本机夹具由维护者提供绝对 PG17.12 和 PostgREST 16.6 二进制路径，通过 Node 测试执行 example-cv-users/tests/s3/support/s38-closed-executor-integration.mjs，环境变量为 S38_TEST_PG17_BIN 和 S38_TEST_POSTGREST。测试在独立临时目录新建 Unix socket 数据库，退场时销毁该夹具。
