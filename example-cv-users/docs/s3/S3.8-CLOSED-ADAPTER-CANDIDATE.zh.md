# S3.8 闭态计划与独立源端证据接口

本地候选从已合并的 #64 复用私有 PostgREST、强制回滚和跨进程持久账本。它可按原 S3.8 矩阵生成 A 14、B 52 项精确闭态计划，核验独立审核过的原件束和逐请求投影。计划仅使用事先冻结的站点、文件版本、已验证 Actor 绑定及唯一原请求 UUID。它不分配身份、生成托管资源、发送请求或改变阶段结论。历史 A 14/14、B 52/52 本地结果继续封存。本次只补受变更影响的本机夹具，不重跑历史托管。

## 计划和源端证据

A 的空库拒绝探针使用预先冻结的不存在对象标识，无需创建实际 A 文件或开放访问。两个计划保持原 RPC、跨站顺序、Owner／UID／SID、精确版本、L1 与 Edge run、闭态 42501／PT503 合同。#64 本地执行器继续只接受隔离 Unix 夹具，复用同一冻结入口和已有原键恢复。供应商源端核对要求独立批准的完整 A 或 B 矩阵，夹具允许单独的本地小样本。入口不接受远端实时访问。

源端包须由独立审核人使用已固定公钥指纹的 Ed25519 签名。审核人从受信渠道取得供应商原件，独立核对数据库目标、时间窗、审核角色、真实调用和决定角色、拒绝分支、SQLSTATE、原请求与 source/transaction ID，并对原始事件如何投影至规范字段负责。原始时间精度留在原件，规范时间为 UTC 毫秒。签名属于独立审核人。原件摘要、原始事件字节区间及其摘要可以检验完整性、阻止替换和重复使用，不能单凭摘要解析各类供应商原始事件的语义。HTTP 回执摘要来自独立传输记录，其形状和同请求映射由本接口检查。接口唯一成功状态为 REVIEWED_SOURCE_BINDING_ONLY，hostedAcceptance 固定为 false。夹具使用本地 PG17.12 日志及 PostgREST 16.6 原响应，合成 Auth 和分支 SQL 指纹的证据边界不变。当前没有经独立确认的供应商原件。

## 真实 Auth 前置

未来接线须独立固定真实目标的 canonical issuer 和可信 JWKS，核对 JWT 签名、iss、aud、exp、批准角色与密码会话用途。GoTrue 的实际账号 UID 和数据库 auth.sessions 中仍有效、属于该 UID 的精确本批 SID 必须与计划绑定，且每次操作前有效。A 必须独立证明账号归零，B 仅可在隔离新目标按合同恢复历史 Owner、用全新 SID，随后恢复停用。断点后不得刷新或换发 SID、JWT，也不得重新登录或重派原请求补证。恢复只读原键证据并按各自合同精确关闭。独立终态包括本批 Session、refresh、资格、临时角色、权限、数据库连接和保护摘要。JWT、Auth 管理凭据和口令不进入证据包。

真实 GoTrue/JWKS 签发与退出、托管 Storage/RLS、供应商源端独立观察及完整 Gate 2 依赖原授权和 SU-570661 技术取证。本次不调用这些服务。S38_LOCAL_READY 保持，HOSTED_GATE_2_NO_GO，FORMAL_DOWNLOAD_BLOCKED。

## GoTrue 与独立会话证明

本地适配器以冻结的 HTTPS issuer、目标数据库指纹和 JWKS 原始字节摘要绑定登录。适配器支持批准的 ES256 公钥集合，只接受带密码用途的有效 `authenticated` JWT。密码回执、GoTrue `/user` 和数据库独立读取必须指向同一个 UID 和本批新 SID。数据库记录必须晚于批准的基线，且须同时存在有效 Session 和关联刷新记录。测试邮箱限于 `example.invalid`。A 的终态要求账号归零，B 要求指定三个 UID 全部恢复停用。两者都须证明会话、刷新记录、活动资格、运行角色与连接已归零。

调用者须在持久账本锁内，以冻结的两个请求键分别派发一次密码登录和一次用户读取。账本仅接收摘要；JWT、口令、刷新凭据不写入账本。登录回执缺失时，保留原意图并按原键独立对账。重开账本只允许关闭，不发起登录、刷新、换发 SID 或重派。启用新 Auth 绑定的本地闭态执行器在每次派发前检查独立会话见证。PostgREST 仍独立验签并使用强制回滚。

适配器没有默认网络客户端或凭据发现路径。真实接线前应独立签认固定 TLS 路径、拒绝重定向与重试策略、目标认证字段、短期 JWKS 轮换及撤销、账号创建或恢复、原键补偿、独立取证执行身份与准确预算。本机新增实库用例使用合成 Auth 和真实 PG17.12／PostgREST16.6，复验签名、精确 SID、源端拒绝和 A 归零。B 定向测试验证三个原 UID 停用、重复或缺失身份及异常未决的失败关闭。历史 66 项本地证据不变。[Supabase JWT 字段](https://supabase.com/docs/guides/auth/jwt-fields) · [Supabase Session 合同](https://supabase.com/docs/guides/auth/sessions)
# 真实本地 GoTrue 复验

两套一次性 PostgreSQL 17.12 集群各使用私有 Unix socket，禁止 TCP 数据库监听。GoTrue v2.198.0 只在本机环回地址启动，用随进程生成的 ES256 签名密钥发布 JWKS。测试从同一实例取公钥并核验原始字节摘要，由 PostgREST 16.6 核验同一套实际 JWT。测试账号使用 `example.invalid`，禁公开注册和投递。

A 从空 Auth 目录启程，建立一个合成账号，执行 14 项闭态调用，以该 SID 精确退出并删除对应账号。B 预置三个独立停用的本地夹具账号，只恢复其中两位 Owner，各登录一次，执行 52 项后精确退出并重新停用。独立只读连接逐次核验真实 `auth.sessions` 与 `auth.refresh_tokens`，源端 SQL 决策同时校验实际账户与会话。终态检查真实账号、会话和刷新记录，以及进程、活动连接和角色口令。关闭还撤销本次运行用的数据库 CREATE、CREATEROLE 及认证角色切换。最后销毁两套一次性数据库。

另有独立故障分支丢失首次源端读回。第二进程在没有 Auth 凭据或写入能力的情况下按原请求恢复，只观察原 PostgreSQL 事件与独立终态，拒绝重送以及继续后续用例。

业务拒绝函数与数据仍属于本地夹具。这里证明真实本地 GoTrue 的身份全程、真实本地数据库角色与源端拒绝；无真实托管源端材料、历史 B 的原生对象或正式业务迁移进入复验。托管 Gate 2 保持 NO-GO。

```sh
S38_TEST_PG17_BIN=/absolute/path/to/postgres17/bin \
S38_TEST_POSTGREST=/absolute/path/to/postgrest \
S38_TEST_GOTRUE=/absolute/path/to/auth-v2.198.0 \
node --test tests/s3/support/s38-closed-executor-integration.mjs
```

未提供 GoTrue 二进制时，三个原生 Auth 用例会明确跳过。常规 Users CI 继续执行无需本机数据库二进制的离线覆盖。
