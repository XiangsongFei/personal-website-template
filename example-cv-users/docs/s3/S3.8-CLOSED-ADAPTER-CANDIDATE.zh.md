# S3.8 闭态计划与独立源端证据接口

本地候选从已合并的 #64 复用私有 PostgREST、强制回滚和跨进程持久账本。它可按原 S3.8 矩阵生成 A 14、B 52 项精确闭态计划，核验独立审核过的原件束和逐请求投影。计划仅使用事先冻结的站点、文件版本、已验证 Actor 绑定及唯一原请求 UUID。它不分配身份、生成托管资源、发送请求或改变阶段结论。历史 A 14/14、B 52/52 本地结果继续封存。本次只补受变更影响的本机夹具，不重跑历史托管。

## 计划和源端证据

A 的空库拒绝探针使用预先冻结的不存在对象标识，无需创建实际 A 文件或开放访问。两个计划保持原 RPC、跨站顺序、Owner／UID／SID、精确版本、L1 与 Edge run、闭态 42501／PT503 合同。#64 本地执行器继续只接受隔离 Unix 夹具，复用同一冻结入口和已有原键恢复。供应商源端核对要求独立批准的完整 A 或 B 矩阵，夹具允许单独的本地小样本。入口不接受远端实时访问。

源端包须由独立审核人使用已固定公钥指纹的 Ed25519 签名。审核人从受信渠道取得供应商原件，独立核对数据库目标、时间窗、审核角色、真实调用和决定角色、拒绝分支、SQLSTATE、原请求与 source/transaction ID，并对原始事件如何投影至规范字段负责。原始时间精度留在原件，规范时间为 UTC 毫秒。签名属于独立审核人。原件摘要、原始事件字节区间及其摘要可以检验完整性、阻止替换和重复使用，不能单凭摘要解析各类供应商原始事件的语义。HTTP 回执摘要来自独立传输记录，其形状和同请求映射由本接口检查。接口唯一成功状态为 REVIEWED_SOURCE_BINDING_ONLY，hostedAcceptance 固定为 false。夹具使用本地 PG17.12 日志及 PostgREST 16.6 原响应，合成 Auth 和分支 SQL 指纹的证据边界不变。当前没有经独立确认的供应商原件。

## 真实 Auth 前置

未来接线须独立固定真实目标的 canonical issuer 和可信 JWKS，核对 JWT 签名、iss、aud、exp、批准角色与密码会话用途。GoTrue 的实际账号 UID 和数据库 auth.sessions 中仍有效、属于该 UID 的精确本批 SID 必须与计划绑定，且每次操作前有效。A 必须独立证明账号归零，B 仅可在隔离新目标按合同恢复历史 Owner、用全新 SID，随后恢复停用。断点后不得刷新或换发 SID、JWT，也不得重新登录或重派原请求补证。恢复只读原键证据并按各自合同精确关闭。独立终态包括本批 Session、refresh、资格、临时角色、权限、数据库连接和保护摘要。JWT、Auth 管理凭据和口令不进入证据包。

真实 GoTrue/JWKS 签发与退出、托管 Storage/RLS、供应商源端独立观察及完整 Gate 2 依赖原授权和 SU-570661 技术取证。本次不调用这些服务。S38_LOCAL_READY 保持，HOSTED_GATE_2_NO_GO，FORMAL_DOWNLOAD_BLOCKED。
