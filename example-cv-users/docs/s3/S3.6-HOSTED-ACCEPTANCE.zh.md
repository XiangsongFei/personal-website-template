# S3 托管验收候选

本地候选基于 PR #56 的 `f1d0ce3d5534c1a4764cdb74b94d89db0328e419`。当前状态为 `HOSTED_LOCAL_CANDIDATE / HOSTED_REAL_NOT_RUN`。托管代码位于 `scripts/s36-hosted`，旧冻结文件、SQL、验收清单和断言保留原字节。旧 REF 保留其独立历史结论。托管项目的应用验收无需等待 `REF_R0_REAL_ACCEPTANCE_PASS`。

受保护 Auth schema 的已有权限即实测输入。首选保持已冻结的内部窄函数与所有权限断言。不将缺失的 SELECT、REFERENCES、角色管理或 schema 权力换成广授权。新项目若在只读预检或原 SQL 检查失败，停止并只针对该项另审前向变更。既有 Users 的 `worker/index.ts`、生产配置、域名与部署入口均在本地测试入口之外。

## 本地入口与参数

从 `example-cv-users` 执行。现有历史原件在工作树 `s3-5-s3-6-assets-publish-20261113` 的 `example-cv-users/supabase/candidates/s36-text-only`。生成器逐件校验 M1–M7、01/02，输出顺序和摘要，并生成目标绑定、默认闭态的 `hosted-project-closed.sql`。它只写新本地目录。

```sh
node scripts/s36-hosted/stage.mjs "$APPROVED_TEST_REF" "$HISTORICAL_SQL_DIR" "$NEW_PRIVATE_OUTPUT_DIR"
```

现场安装前使用 `supabase/candidates/s36-hosted/preflight.sql`。从项目 Connect 页面记录固定目标。Direct 走 IPv6 的 `db.<ref>.supabase.co:5432`，使用数据库登录角色名。IPv4 使用该项目的 Supavisor Session 节点，端口 5432，用户名为 `<角色>.<ref>`。两者都使用 `verify-full` 核验 CA 和主机名。当前 Mac 没有读到默认 IPv6 路由，现场优先预检 Session Pooler。必须实测后端 `session_user` 与固定登录角色一致，验证角色切换和 PostgreSQL 17。清理继承的 `PG*` 配置，凭据放在单独的 0600 文件。部署器使用 `psql -X -v ON_ERROR_STOP=1` 与已审 manifest 顺序逐文件执行，出现第一项错误即停。已有对象冲突、错误签名验证或权限不足后，检查已提交迁移及目录并对账，勿自动重跑。包的最后阶段仍是闭态。

本地 CLI 使用 Users 的 `createIdentityAdapter`、`createSiteService`、`createRpcRepository` 和私有入口。配置 JSON 必须 0600，字段为 `project`、`publishableKey`、`privateOrigin`（带端口的 `https://127.0.0.1`）、`alice`、`bob`（Auth UID）、`aliceSite`、`bobSite`、`entry`（Alice 默认简介条目 ID）、`requestId`、`expectedDraftRevision`（首轮固定 0）。拒绝 Users/CMS 生产项目、非 loopback 业务入口及 secret/service key。Auth URL 从项目 ref 构造，拒绝跨目标请求和重定向。

- `connection.json` 保存 `project`、`publishableKey` 和 `privateOrigin`。两个 JSON 凭据都按 0600 保存。数据库描述为 `project`、`mode`（`direct` 或 `session`）、`host`、`ca`（PEM 文本）和仅属于该登录角色的 `password`。应用进程持有普通用户 access token 和本机 mTLS 证书。PostgREST 与独立 registrar 使用不同的 PostgreSQL 登录密码，均从各自的私有描述传入。管理员凭据只用于部署、夹具准备和独立读回。
- `postgrest.mjs` 固定 Unix socket 路径、0770 父目录、0660 socket、仅 `site_api`、PG 登录 `ecv_s3_internal_api_login`、目标 Auth 公共 JWKS 和 `authenticated` audience。原生程序由操作员确认版本和绝对路径。私有 PostgREST 材料包含 `database`、`socketPath`、`caFile`。HTTP 业务入口独立，仅监听 TLS loopback。ingress 文件含 CA、证书、私钥、客户端 `trustedFingerprint` 和同一 `socketPath`。禁止向托管 Data API 暴露三个业务 schema。 macOS 上在进程启动前核对套接字目录的实际 UID 和 GID 分别等于 `id -u` 和 `id -g`。若 `/private/var/tmp` 下新建的专用目录继承了 `wheel`，只将该目录的组设为当前进程组，再核对模式仍为 `0770`。生成本地 mTLS 证书时使用 RSA 或具名曲线 EC。Node 拒绝带显式 EC 参数的证书，即使 OpenSSL 可以读取该证书。
- 闭态安装后，仅对这两个专用角色设置本项目独立密码和 LOGIN，保留 M6/M7 的继承、SET ROLE、连接数及无管理权限约束。先验证两条 SSL 登录、角色和 PostgREST/JWKS，再在项目 Auth 中创建两个确认邮件的合成账号。以安装清单中的 `activate-first-save.sql` 校验安装的九个函数定义、角色、锁、关闭状态及测试 UID，依据审批转换 M5 保留的闭态闩。保留 `business_gates_agree`、实时 Session/Grant/epoch/generation/Owner 与 RLS/ACL。只为这两个 UID 建安全状态和短生命周期的签署代次，保持 publish/unpublish、公开读取和 outbox 关闭。
- `grant-sites.mjs` 的私有夹具需要 `project`、`generation`、registrar 的 `database`、客户端 `tls`、`alice`、`bob`、`saveRequestId`。generation 字段为 `project`、`id`、`keyHex`（256 位）、`notBefore`、`signUntil`、`verifyUntil`（与激活事务一致的 UTC 秒）。每个账号包含 `credentials`（email/password）、`approval`（uid、proofId、epoch=0、validFrom、expiresAt）和 Users 的 `createRequest`（schema_version=1、request_id、slug、default_locale）。每个 proof 绑定真实密码登录回执的 UID 与 SID，签署前写入持久消费记录。专用 `ecv_s3_registration_login` 只发送一条固定参数化登记查询，由原 M5/M7 检查 generation、角色和 proof，再由同一个普通用户 Session 调用 `apply_business_grant` 与 `create_site`。脚本成功后把 Session 与验收配置写入新的 0600 文件。切勿把凭据、同键回执或本地 fixture 日志上传。

```sh
npm ci --prefix scripts/s36-hosted
node scripts/s36-hosted/postgrest.mjs "$CONNECTION" "$POSTGREST_MATERIAL" "$NATIVE_POSTGREST_BIN"
node scripts/s36-hosted/ingress.mjs "$CONNECTION" "$INGRESS_TLS_FILE"
node scripts/s36-hosted/grant-sites.mjs "$CONNECTION" "$APPROVED_FIXTURE" "$PRIVATE_BATCH"
node scripts/s36-hosted/acceptance.mjs "$PRIVATE_BATCH/acceptance.json" "$PRIVATE_BATCH/acceptance-secrets.json" "$PRIVATE_BATCH/first-save.json"
```

测试先确认匿名请求被真实 ingress 拒绝，然后用真实 Session 检查 Alice/Bob 均有自己站点的读取资格。对 Bob→Alice 和 Alice→Bob 分别要求读取、写入明确拒绝，再由 Alice 对初始文案保存一次固定合成内容，核对 revision 1、Bob 不变、原请求 ID 的事务回执。以 `psql -X -v ON_ERROR_STOP=1` 单独运行 `supabase/candidates/s36-hosted/observe-first-save.sql`，传入 `alice`、`alice_sid`、`alice_site`、`bob_site`、`request_id` 五个变量。须读回真实结果、revision、actor/Session、同一操作的审计关联和 unpublished 指针。应用成功仍显示 `APPLICATION_CHECKS_PASS_AUDIT_PENDING`，独立审计通过才合并判定。此批跨站指跨站点 ID；浏览器 CSRF 和 UI 另测。

## 下一次执行范围

1. 确认全新 `example-cv-s3-acceptance`、Singapore `ap-southeast-1`、PG17、实际组织/项目 ref 和费用。现有可见的 Example CV 组织是 Free，两个项目都是生产项目。连接器对该 Free 组织返回 USD 0/月费率。两个已占用名额使它无法作为第三个可用项目的报价。Free 同一 Owner/Admin 的名额跨组织计算。独立 Pro 组织单个 Micro 的公开基价为 USD 25/月（订阅 USD 25 + Micro USD 10 − 计算抵扣 USD 10），当前账户尚无独立组织和实际结账报价。保持默认消费上限，不选择附加项。共享 Session Pooler 无需购买专用 IPv4，若日后明确购买则官方单价 USD 0.0055/小时，约 USD 4/月。
2. 对选定新项目只读核对版本、空 catalog、当前 Auth 列权限、角色委托、业务 schema 及默认 ACL；另核查私有 PostgREST、两个登录身份、登记 TLS 方案及正式运行材料。只读能力失败立即停止，原迁移的权限断言继续生效。提交第一份迁移前在目标回读 SSL、角色、Auth 读取、外键权限、扩展和命名碰撞。
3. 写入边界为该项目的 M1–M7、01 和独立审阅后的闭态迁移。激活脚本另列摘要，使用同一批准批次内的激活检查点，只允许此目标、两测试 UID、专用角色及代次。绑定真实 Session、保持 Grant 默认拒绝、保持 publish/unpublish、public read 和 outbox 关闭。夹具限两个确认测试账户、两站、固定默认文案及一条 Alice 合成保存请求。禁止真实个人数据、Storage 及生产同步。
4. 按入口执行负例和 Alice 保存，独立读回。目标/权限漂移、负例没有明确拒绝、版本/审计不一致、首次写入后回执丢失立即停止。保留原 request ID 和本地 journal，按同键只读对账。收尾关本地监听并按批准的保存策略处理测试会话和凭据；资源处置另行确认。
5. 首轮真实通过后再扩展并发 CAS、同键幂等重放、故障回滚、UNKNOWN、会话/Grant 撤销、发布与撤回，随后评估 02 和 S3.5。托管证据可验证业务边界与事务。它无法证明旧 REF 的固定版本、SID、4 GiB 路径、ENOSPC、Watchdog、UTM 启动或历史 A07/A50 边界。
