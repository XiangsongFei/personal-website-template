## SQL 异常回滚

保存事务仍为 `PARTIAL`。`site_api.save_text_draft` 调用 `s36_apply`。后者先认证、锁定、校验输入、同键和 CAS，再写操作回执、草稿历史、section/site revision 与文本审计，返回前重验实时资格。三处相关完整性约束分别针对材料摘要、单调前驱和事务效果。已核对业务函数、约束触发器及数据库目录。事务函数没有吞掉异常的 EXCEPTION 分支。可控的正常拒绝发生在写入前，写后可能抛错的路径依赖完整性破坏、时序碰撞或资格变化，当前没有能绑定到一次合法 Alice 请求并证明已写入的稳定入口。既有 22012 夹具针对安装事务，已通过的强制回滚属于事务结束策略。RPC 内部 SQL 异常保持 `NOT_RUN`。

供另审的最小方案限一次测试请求。保留原 RPC 和迁移字节。另批批准后，在专用测试目标临时安装一个由既有只读完整性角色 `ecv_s3_integrity` 拥有、空 `search_path`、无 PUBLIC EXECUTE 的 SECURITY DEFINER 触发器函数，以及一个附在 `site_private.text_publication_audit` 的 AFTER INSERT 约束触发器。触发器先按保存 action、Alice site、actor UID、真实 Session、预期 revision 和新 operation ID 缩小匹配。在同一事务内用 operation ID 读回已写但未提交的操作回执、canonical 请求摘要、草稿历史、site/section revision 和当前未发布指针。仅在完全匹配已批准 request_id、摘要和 revision 时抛出专用 SQLSTATE（例如 `PZ036`），错误诊断只保留固定标记和合成测试请求 ID。其他请求直接返回。测试入口维持真实 Session/Grant、Owner、RLS、PostgREST 与 mTLS。通过私有测试日志独立确认错误来自该请求，避免把普通 503 当成注入成功。单独只读核对所有写入回滚、旧回执和 Bob 未变。收尾先停测试入口，再在一个受限事务中精确 DROP 该触发器和函数，核对名单及目录前后差异。保留错误和对账证据。未创建或安装这些对象。

现有 02 SQL 没有依赖 SQL 异常证据的运行时或安装条件。该证据仍是保存事务全项 PASS 的必要条件。可以独立准备发布验收。是否在保存事务为 PARTIAL 时批准独立测试项目执行发布，由下一批审批显式决定。完整 S3.6 和生产放行不得据此写成已验收。

## 02 和发布边界

- 02 原件 SHA-256 为 `c6747937f2ea3624b246eea3d004b8f4142f02d52861e9e8a4476aecb38a2d88`。原件主版本限定 PG17，35 条 SQL 语句和 15 个 PL/pgSQL 块通过 PG17 语法检查，复合类型仅在本地解析投影中替换为 record。所需托管 `postgres`、OID 10 `supabase_admin`、既有表及角色前置已只读核对。02 尚未在真实 PG17.12 上编译或安装。
- 02 单事务为 Outbox 新增 NOLOGIN/NOBYPASSRLS 工作者、11 个私有函数、4 条限角色策略和 2 个保护触发器。保留 FORCE RLS，只增事件有限列的 UPDATE，不能修改发布指针。权限断言拒绝额外授权。安装内的临时部署角色继承及 SET 权在提交前撤销，保留原始 bootstrap admin-only 边。02 不打开任何开关，不授普通角色 worker 函数执行权，也不增加登录身份。
- 发布/撤回走既有 `site_api → s36_apply → lock_business_qualification`，使用真实身份、当前 Grant、epoch、有效授权和同站 Owner。数据库先检查资格，再同键回放，再做 CAS。指针永久行禁止删除，发布 revision 每次有效变化恰加一。快照固定指向同站不可变草稿历史，未发布的后续草稿保存不修改公开快照。指针、历史、审计、操作回执和事件在同一事务写入，延迟约束检查效果完整性。
- 现有账号和站点可以继续使用。发布需要新的真实登录和窄 R3 Grant。两个域名当前 reserved，本批不改变。已用只读事务内的 `anon` 角色调用原函数并确认闭态返回 `PT404`。下一批公共投影探针在一个事务内临时启用 Alice 唯一 test 域名和 public gate，用 `SET LOCAL ROLE anon` 调原匿名 RPC 后 ROLLBACK。对外 Data API 及 DNS 从未获得该事务中的状态。
- Outbox 以固定 event ID、lease token、generation 和到期时间认领；attempt cap 为 3。开始投递后失去确认进入终态 UNKNOWN，禁止补发。明确失败才可在到期后显式重领。确认检查当前 publication revision/state，过时事件只可 superseded。候选探针在一次回滚事务中验证领取、重复 start 拒绝、失败重试和 UNKNOWN 终态。无 sender、无对外投递。此探针不代表持久 worker 并发、真实网络投递或外部去重已经通过。

## 下一批审批和预算

仅在用户另批批准固定项目、源码、SQL 摘要和执行范围后运行。项目 ref 必须仍为 `vellypyadcxkvqftsbrg`。闭态目录前后检查分别使用 `publication-catalog.sql` 的 `expected_02=false/true`。安装 02 一次。复核 Management API 的 exposed schemas 和数据库 `pgrst.db_schemas` 覆盖均不含 `site_api,site_private,site_data`。两份历史用户和站点必须匹配只读证据；如发现 02 半提交、额外主体、活跃发布、角色/ACL/RLS 漂移或已有计划键，停止。

1. 以已批准的 `publication-generation.sql` 写入一个最长 30 分钟的代次。用现有 Alice/Bob 凭据作各一次真实登录、两次 registrar 登记和两次 Grant，另外 Alice 作一次无 Grant 登录。历史 Alice 已过期访问令牌只用于拒绝用例。新用户、新站点、撤销均为 0。
2. 同一 loopback 私有入口的连接 JSON 仅加 `publicationSite=<Alice site UUID>`。沿用两专用登录、Unix socket、已验证 TLS/mTLS。仅批准 `publication-acl.sql` 启用一次两个发布 RPC 的 authenticated EXECUTE，并保留一次 `action=close` 收尾权限。不得在 Data API 暴露业务 schema。公开读取及 Outbox 开关在所有已提交状态保持关闭。
3. 固定 4 个不同于历史回执的 UUID，分别绑定拒绝用例、发布、新草稿保存和撤回。匿名、过期令牌、Bob、Alice 无 Grant Session 对同一拒绝键共尝试 4 次，要求明确的 403 且快照无变化。正向仅 Alice 发布一次（草稿 4，发布 0→1）、未发布草稿保存一次（草稿 4→5，指针仍指向 4）、撤回一次（发布 1→2，指针清空）。三个正向原键各正常只读对账一次。
4. 公共投影事务共 4 次，分别核验发布前 404、发布后快照、修改草稿后同一公开投影和撤回后 404。只观察英文已发布内容。Outbox 回滚探针一次，仅检查该站两条事件，真实发送 0 次。最终两条持久事件仍 pending、快照及审计保留。恢复两个发布 RPC 的闭态 ACL，再独立验证闭态目录并停掉本地服务。若中途停止，先停止派发并保留证据；已批准的 ACL 关闭可独立执行，不自动撤回业务指针或重放请求。

任一身份、摘要、版本、角色、schema 暴露、授权、ACL 或回执异常即停止后续写入。明确业务拒绝必须匹配预期错误码。写入 UNKNOWN 只允许对原键查询一次业务回执并独立对账，不换键、不重发、不继续下一次写入，即使对账发现已提交。保留原始回执和所有已提交记录；不删除历史，不连接正式网站、Cloudflare 或外部发送目的地。
