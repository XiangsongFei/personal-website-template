# S3.5 私有 PNG 生命周期候选

该组件用于受控服务组合。现有 Users 路由、生产装配和数据库 SQL 都未变化。正式文件下载继续 BLOCKED。

## 信任与接线

- 构造方冻结项目、发行方、run、Owner 与独立 Storage Worker 的 UID/SID、站点、Grant、验证器工件摘要、Seal／complete 执行角色、PNG 字节摘要及各阶段唯一请求键。正常入口要求两位不同的有效主体。恢复入口使用原冻结计划和私有账本，仅允许对账与关闭。
- prepare、claim、authorize-verify 调用主线已有的授权实现。它们继续分别核对数据库当前资格并关闭自己的命令租约。生命周期账本在每次作用前落盘。关闭观察器须按三个原命令和命令关闭键独立确认没有活动租约、在途请求或晚到提交。外层 close 是独立批准的同 run 安全操作，可关闭原范围内尚存的租约，即使某次业务提交仍未知。它的适配器必须约束实际权限、排除不安全并发并保护已提交文件。
- 上传使用精确数据库分配键、Worker 凭据及固定 create-only POST。claim 的独立回执须证明精确应用 POST UUID 已与当前 Worker、对象及 Permit 原子绑定。受信传输接收该 UUID 及 claim XID，Storage 最终触发器须用相同绑定提交。HTTP 请求头或响应本身不能决定该归属。独立源还需证明同请求的 Permit 消费、外部 Worker 绑定、Storage 执行身份、版本和最终 XID。外部 Storage 请求身份是 Worker 的 authenticated；历史触发器最终上下文是 supabase_storage_admin／service_role，独立与普通业务 RLS 验收区分。
- Verifier 通过调用方提供的批准私有路径绑定同一原生版本。组件再次完整解码、重算长度和 SHA-256，并在读取后独立核对资格。Verify 回执保存在受保护的本地不可变证据中，使用独立读回，没有数据库 XID。Seal 与 complete 分别需要同回执摘要、同对象、各自的真实提交 XID 与执行角色。complete 的受信源端事务须检查原 Seal 请求及 XID 已提交且摘要一致。独立终态再次核对保留的 Seal、complete XID 与回执摘要。
- 写入回执不明时不重发，也不继续后续业务。独立读取原操作和所需前置证据，复核同一 prepare、claim、POST、原生版本、POST XID 及 Verifier 回执。冲突、未决或仍可能晚到的原操作保留 UNKNOWN。关闭回执必须证明资格、角色与连接闭态，保护目录和原生对象需保持原样。

## 验证与边界

从仓库根目录运行。

```sh
node --test example-cv-users/tests/s3/private-png-lifecycle.test.mjs
S35_TEST_PG17_BIN=/absolute/path/to/pg17/bin node --test example-cv-users/tests/s3/support/private-png-lifecycle-postgres.mjs
```

定向测试覆盖完整顺序、身份和正文绑定、版本、缓存、资格撤销、错误回执、保留对象及原键恢复。PG17.12 夹具使用独立无 TCP 的数据库、分离观察身份及真实事务 XID，强制终止两个写入进程并由新进程接续关闭。Auth、Storage 服务及平台角色见证均为合成。生产部署、实际 Storage/RLS 和供应商角色见证仍需经批准的独立准入。
