## 两条调用链

普通 Worker 的业务 Repository 仅接受固定项目的身份适配器产生的句柄和专用出站 mTLS binding。目标仅为候选内网 DNS api.ecv-s33a-20261109-7dd22a81.internal.test 的 HTTPS 端口 443。每次只发一个 POST，携带原始用户 JWT。私有 Node HTTPS 入口要求 CA 校验客户端证书并精确匹配 Worker 叶证书 SHA-256 指纹。拒绝重复头、重复 JSON 键、额外参数、客户端 Profile、任意 URL 和伪造的对端头。流式读入上限 8192 字节，上游响应上限 65536 字节。逐个请求独立核验 Auth 句柄；对登记票据另核对同一用户及会话。

入口通过独占的 /run/ecv-s33a-internal/postgrest.sock 发送请求，重建 site_api Profile 和五个白名单 RPC 的参数。私有 PostgREST 以单独的验证密钥材料验证原始 JWT，限定 jwt-aud=authenticated 和固定 role 声明；小心区分 Auth 签名和 Proof HMAC。上线前还须冻结算法、issuer、可信公钥集合、kid、时钟、禁匿名角色、不受请求影响的配置，以及独立 Unix socket 的父目录、所有者和客户端权限。隔离其管理接口，禁止转发任意 SQL、GUC、Profile、Prefer、Cookie、管理员密钥或请求头。拒绝库连接池身份串用。公共 PostgREST 保持仅 public。私有 Node 入口仅提供构造函数，仓库没有监听或部署入口。[PostgREST 16 Unix socket 配置](https://docs.postgrest.org/en/stable/references/configuration.html#server-unix-socket)

五个函数为 apply_business_grant(envelope)、create_site(input)、read_create_operation(input)、get_my_site()、read_introduction(target)。Worker 的敏感请求进程不共享登记端 TLS 材料。专用验证组件完成原协议 HMAC、身份和意图检查，再由独立客户端使用登记证书，目标候选为 pg.ecv-s33a-20261109-7dd22a81.internal.test:5432/postgres。连接固定 ecv_s3_registration_login，要求 TLS 1.2+、专用 CA、唯一精确 DNS SAN 和成功的 hostname 验证。仅接受 ca、cert、key 三项受保护材料；数据库要求密码时立即拒绝。会话携带的数据库权限只足以执行 register_business_ticket(jsonb)。当前没有安装 PG 客户端依赖或配置证书。需要专门冻结具体驱动并实测能执行这些 TLS 回调；不支持即停。

JWT 验证依赖部署方注入的真实可信实现。数据库信任经过认证的私有 PostgREST 建立的事务上下文。窃取该服务的连接能力或获得任意 SQL 能力可伪造 claims GUC；窃取登记凭据可登记伪造声明。两者不得挂载到浏览器、普通 Worker 或彼此的进程。私有入口和 registrar 使用不同的 CA/叶证书或严格的独立用途和身份映射。按服务轮换、封锁旧凭据并核验已建立连接。禁止日志包含 Token、票据全文、证书私钥、数据库认证材料。出现不完整响应仅按原 proof_id 或 request_id 对账，禁止重签、自动重发和新 ID 补偿。

## 原实例传输与生产差异

当前数据库 ssl=off。既有 postgres 的 Unix socket 连接实际使用 peer；其他服务身份的首匹配 HBA 仍 UNKNOWN。若未来需要本地资格测试，优先采用两个受限 OS 主体、互不通用的 socket 权限和精确 peer/ident 映射。仅可在证明目标目录/端点不可替换且拒绝其他 OS 身份后另批本地专用适配器。本候选证书客户端没有明文 fallback。当前 0777 socket 本身不能提供进程隔离证明。另一选择为未来经独立批准的受保护代理，要求代理到原库的最后一跳同样具备经核验的服务身份，禁止宽泛的任意 SQL 转发。

正式远程链路要求实际服务 DNS、路由、CA/SAN 验证及独立客户端身份；公共 Workers 的 mTLS fetch 与私有路由可达性需分别验收。Cloudflare 指明经过其代理的目标 zone 有 mTLS outbound 限制。候选 .test 域名仅用于固定隔离合同。若托管 Supabase 不支持所需证书映射或池连接不能保留 session_user，另审受控内部连接服务或每服务 verify-full + SCRAM 设计。保留原 libpq 三次握手证据，真实 Worker 驱动验证独立计数。[Workers mTLS](https://developers.cloudflare.com/workers/runtime-apis/bindings/mtls/) · [Workers TLS 兼容范围](https://developers.cloudflare.com/workers/runtime-apis/nodejs/tls/) · [PostgreSQL 17 证书验证](https://www.postgresql.org/docs/17/libpq-ssl.html)

HBA 专项只读授权范围为固定集群中一个已有足够权限的本地主体、一次新连接、BEGIN READ ONLY 与明确 ROLLBACK。核查服务数据库/角色、拟用 OS 身份、源地址、TCP/TLS 或 local、规则实际顺序、include 展开、第一匹配的认证方式、映射与配置是否成功加载。处理磁盘文件与已加载配置的差异，后续用真实专用主体确认结果。允许在同事务中仅为命中的 map 检查 ident 映射；仅输出匹配结论、行号/序号、方法和错误存在布尔量。禁止读取认证材料、导出 options 原文、授目录权限或修改 HBA。遇 42501 停止。[PostgreSQL 17 HBA 匹配规则](https://www.postgresql.org/docs/17/auth-pg-hba-conf.html)
